# Playtest Scheduler

A small static web tool for running Playtest UK evenings in London: check people in, capture who's bringing a game, generate a session schedule in one press, and copy it straight to WhatsApp.

It's a vanilla JavaScript single-page app with no build step and no runtime dependencies. It runs entirely in the browser and stores its data in `localStorage` on the device you use it on.

## Running it locally

From the project folder:

```
python -m http.server 8765
```

Then open http://localhost:8765 in a browser. ES modules need to be served over HTTP (not opened as a `file://` page), which is why the app needs a local server even though there's no build step.

## Installing the Meetup import bookmarklet

Open `bookmarklet.html` (linked from the Evening tab as "Install the Meetup import button"). It gives you:

- **Desktop**: drag the "Playtest import" link straight to your bookmarks bar.
- **Phone (Chrome on Android / Safari on iOS)**: create any bookmark first, then edit its URL and paste in the bookmarklet code (there's a "Copy bookmarklet code" button and step-by-step instructions on the page).

To use it: go to your Meetup event's attendees page and tap the bookmarklet. It scrolls to load every attendee, reads the attendee list and event details, fetches the event page for comments, and copies a JSON payload to your clipboard (or shows it in a text box if the clipboard isn't available). Paste that into the "Import from Meetup" box on the Evening tab.

Known limits:
- This hasn't been tested against the live Meetup site yet, only against saved sample pages.
- The bookmarklet code is about 26,000 characters long, which may be awkward to paste into a bookmark on a phone.
- Comment fetching prefers Meetup's internal `__NEXT_DATA__` data (unverified on live pages) and falls back to reading the comments straight off the page; that fallback may only see the first page of comments if Meetup shows a "More comments" control.

## Weekly workflow on the night

1. **Evening tab** - set the date, start time and evening end window, and import from Meetup (paste the bookmarklet output, or a plain list of names).
2. **People tab** - check people in as they arrive ("Here"), and enter each designer's game (testers min/preferred/max, duration).
3. **Schedule tab** - press **Schedule** to generate options; pick one (or the best is pre-selected).
4. **Copy to WhatsApp** - press "Copy for WhatsApp" to get the exact session list formatted for the group chat.
5. **Post-its** - open "Post-it view" for large-type end times and designer names to copy onto post-it notes for each table.
6. **Mark played / Replan** - as each session finishes, mark it played; the app locks it. If someone leaves early or things change, press **Replan** (the Schedule button becomes **Replan** once a session has been marked played) to reschedule only what's left, keeping played sessions untouched.
7. **Finish evening** - saves the evening to the Log.

## Data and backups

Everything is stored in the browser's `localStorage` under three keys: `gm.roster` (people and their usual game settings), `gm.evening` (the evening in progress) and `gm.log` (past evenings). This data lives on one device, in one browser, and isn't backed up anywhere else.

Use **Export data** (on the Log tab) regularly to download a JSON backup, and **Import data** to restore from one. **Clear roster** (also on the Log tab) wipes the stored people list.

## Scheduling rules, in brief

- Only people marked "Here" are considered.
- Every present designer's game is played exactly once (already-played/locked sessions aren't rescheduled).
- The organiser's game always goes in Session 1.
- New sessions are all the same length and run back-to-back from the start time (or from the replan point) to a chosen end time.
- Testers are split across tables aiming for each table's preferred count, within its min/max; if there are too many people, spare designers become watchers rather than overfilling a table, and only as a last resort does a table go over its max or a game go unscheduled.
- Among otherwise-similar options, the scheduler prefers using the evening fully, keeping sessions in the 45-60 minute range, and minimising watchers.

The full algorithm lives in `js/scheduler.js`.

## Tests

```
npm install
npx playwright install chromium
npm test               # unit tests (node --test "tests/**/*.test.mjs")
npm run e2e             # end-to-end browser test (Playwright, headless Chromium)
npm run build:bookmarklet   # regenerates bookmarklet.html from bookmarklet/meetup-bookmarklet.src.js
```

`npm install` pulls in the dev-only dependencies (`jsdom` for the unit tests, `playwright` for the end-to-end test) - the app itself has no runtime dependencies. `npx playwright install chromium` fetches the browser the e2e test drives.

Don't hand-edit `bookmarklet.html` - it's generated by `npm run build:bookmarklet` from `bookmarklet/meetup-bookmarklet.src.js` and `js/meetup-import.js`.

## Privacy

The sample Meetup pages used to build test fixtures (and anything decoded from them, under `tests/fixtures/`) contain real attendees' names and photos. They're excluded via `.gitignore` and must never be committed or published.

## Publishing to GitHub Pages

Not done yet. The repository (https://github.com/wombatgamefactory/playtest-scheduler) is currently **private**, and GitHub Pages on a private repository needs a paid GitHub plan. To publish:

1. Either make the repository public, or confirm you're on a GitHub plan that supports Pages on a private repo.
2. Push the current work to `origin`.
3. In the repository's Settings → Pages, set the source to deploy from the `main` branch (root).
4. Check the published site works, then share the `github.io` URL.

Remember the Meetup sample/fixture files are gitignored and won't be pushed - nothing private goes live.
